## Design Specificity Verdict

**Strongly product-specific where it counts; coasting on convention in the back pages.**

**LLM assessment:** This is not a template. The **registration rail** (EventsPage `regDays`/`MonthGrid`/`RegLead`) renders the *registration window* as colored territory spanning calendar days, urgency-tinted, with rounded caps only on true start/end — it encodes the Badminton Québec draw-math rule directly into the visual language. The **completion moment** (Celebrate.tsx `CheckCircle` → `complete-swell` + particle burst) and the **single-spring motion system** (`--ease-spring` used everywhere) read as "one hand made it." Blue-cast shadows, an aurora canvas, and a violet-not-slate neutral ramp are real authorship. It thins out in Career (stock kanban), Academics, and Settings (conventional label-over-input forms) — competent but category-interchangeable.

**Deterministic scan:** detector exit 2, **2 findings**, both `bounce-easing` on `--ease-spring` (index.css:178, :210) — **both false positives**: it's a subtle ~8% `linear()` overshoot, the committed signature spring, not a dated elastic bounce. No hardcoded-color / radius / gradient / shadow slop fired — the token system is otherwise clean. Independent evidence pass confirmed: **`text-faint #5d6d91` fails WCAG AA 4.5:1 on every surface** (3.64 / 3.29 / 2.87), used widely for small text and placeholders; **three inputs suppress/omit the focus ring** (TaskEditor.tsx:425, TasksPage.tsx:373, TimeField.tsx:181); a **raw-hex dot-color map** in EventsPage.tsx:27-31 duplicates existing tokens. ARIA/roles, alt coverage (0 `<img>`), non-button clicks, and reduced-motion are all clean.

**Visual overlays:** unavailable — no browser-automation tool is exposed, and the Electron renderer needs IPC to show real data, so a plain dev server renders empty. Review is source + deterministic evidence only; no overlay was produced.

## Overall Impression

A genuinely crafted, opinionated personal tool with a clear point of view — the motion, the palette, and the registration rail are the work of someone who cares. What holds it back from "Good" isn't taste, it's **finish**: three dead tokens shipping broken UI, a contrast token that fails AA in daily-read spots, and destructive deletes that skip the safety net the rest of the app uses. The single biggest opportunity: **close the finish gaps** so the craft you already have reads as reliable, not just pretty.

## What's Working

1. **The registration rail** — it inverts the naive model (the deadline *is* the window, not the tournament) and renders it as spatial territory with urgency in hue. Design in service of the owner's real anxiety: missing registration.
2. **The single-spring motion system** — every tactile element shares `--ease-spring` + `scale(0.97)` on `:active`; completion replays via class-toggle so it survives re-bucketing. Reads as one considered hand.
3. **Empty-state & micro-copy voice** — "your weekly lab belongs here", "the cycle starts with Push", "registration fills fast." Copy does brand and onboarding work at once.

## Priority Issues

**[P0] Three dead design tokens ship broken UI**
- **Why it matters:** `.led` (SettingsPage.tsx:69), `accent-(--color-amber)` (EventsPage.tsx:800), and `bg-surface2` (EventsPage.tsx:13, CareerPage.tsx:807) reference classes/vars defined nowhere. The Groq "key stored" LED renders as an invisible span, the alarms checkbox falls back to raw browser accent, and two chips/buttons get no background — silent failures on the exact surfaces where the user needs certainty.
- **Fix:** Define `--color-surface2` and `--color-amber` in `@theme` and add a `.led` rule, or swap to existing tokens (`bg-raised`, `--color-gold`).
- **Command:** `/impeccable harden`

**[P1] `text-faint` fails WCAG AA contrast, and it's used widely**
- **Why it matters:** `#5d6d91` on the dark surfaces computes to 3.64 / 3.29 / 2.87:1 — below AA 4.5:1 for the small text it carries (sidebar labels, weekday headers, "+N more", counts, and most input placeholders). Opacity-reduced `text-muted/60`, `/50`, `/40` push several more below AA. This is daily readability friction for the owner and a hard fail for low-vision users.
- **Fix:** Lighten `--color-faint` (or reserve it for ≥18px/bold only) and stop multiplying `muted` by opacity for body-size text; verify each usage clears 4.5:1.
- **Command:** `/impeccable audit`

**[P1] Destructive row actions bypass the confirm/undo the rest of the app uses**
- **Why it matters:** Task delete (TaskRow:474) and event delete (EventRow:864) fire instantly, while tags, courses, lectures, and applications all confirm. Inconsistent safety is worse than uniformly unsafe: the user learns "delete asks," then loses their highest-frequency object to a misclick.
- **Fix:** Route both through `useConfirm`, or add an undo toast mirroring the gym Undo pattern.
- **Command:** `/impeccable harden`

**[P2] No global keyboard accelerators for a daily desktop tool**
- **Why it matters:** All shortcuts are field-scoped. No `n` = new task, no `/` = focus quick-add, no digit keys to jump sidebar sections, no multi-select/bulk-complete. The owner reaches for the mouse for every context switch — friction that compounds daily. Also leaves H10 (help) empty.
- **Fix:** App-level keymap (`1-8` sections, `n` quick-add, `?` opens a shortcut sheet that doubles as the missing docs); checkbox multi-select + bulk actions on Tasks.
- **Command:** `/impeccable optimize`

**[P3] Consistency drift: idioms, radii, delete affordances, off-token colors, focus gaps**
- **Why it matters:** On an Operate surface, consistency *is* scanability. Two input styles, four delete affordances, button radii 10/11/13/14px, a raw-hex color map (EventsPage:27-31) duplicating tokens, three inputs that drop the focus ring (TaskEditor:425, TasksPage:373, TimeField:181), and two empty `<span>` placeholders (CareerPage:354, :811) — subtle, but the line between "crafted" and "assembled by sections."
- **Fix:** Promote the TaskEditor input + Popover field into shared primitives; lock radii to the two theme tokens; standardize one delete affordance per context; move the dot-color map onto tokens; restore focus rings.
- **Command:** `/impeccable distill`

## Persona Red Flags

**Alex (power user):** No global shortcuts; can't add a task or switch sections without the mouse. No bulk complete/delete — 10 done tasks = 10 clicks. Job feed paginates by 40 with no "show all."

**Sam (accessibility):** `text-faint` at ~3.3:1 is the biggest liability (widely used small text). Task priority is a bare 7px colored dot — meaning by hue alone, no shape/text. Focus visibility is otherwise *excellent* (`@layer base :focus-visible` can't be suppressed by utilities) except the three inputs that opt out. Roles/aria are solid.

**Riley (stress tester):** Task rows with 6 tag pills + priority + date + repeat + bell will crowd the single-line row. No list virtualization anywhere — fine now, a latency cliff at hundreds of tasks. In-page state (open editors, unsaved quick-add, selected day) resets on reload; only the hash-based view survives.

**The owner (busy EE student, daily):** Will resent the instant task delete the first time it bites, and no keyboard-add every day. `faint` contrast makes counts/version/placeholders hard to read in a bright room. Will love the one-tap gym log, the reg rail, and the completion burst.
